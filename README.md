# 地推商圈分析工具 v0.2.0

线下地推辅助工具：抓取餐饮POI → 规则+可选AI筛选独立餐饮（排除连锁/奶茶/卤味）→ 按商圈聚合"用工需求热度"→ 地图可视化呈现。

**核心场景**：你要在一个城市做日结/短期用工类产品的地推，打开工具选定城市/区域，几分钟后地图上就显示"哪个商圈值得跑、哪些店优先拜访"。

> **v0.2.0 的核心变化：整条链路默认零成本。**
> 不再需要 DeepSeek 充值，不再受高德每月 1 万次配额卡脖子，也不用再折腾那个动不动就白屏的 `securityJsCode`。
> 从旧版升级请看 [第七节](#七从-v01-升级)。

| 环节 | 用什么 | 免费额度 | 要不要钱 |
|---|---|---|---|
| POI 数据 | 腾讯位置服务 | **10,000 次/日** | 免费 |
| 地图底图 | Leaflet + 天地图 | **10,000 次/日** | 免费（Leaflet 已随代码打包，不依赖 CDN） |

想要更聪明的打分？可选接免费大模型（见[第五节](#五三种打分引擎怎么选)），依然零成本。

## 二、准备工作（10 分钟）

### 1. 申请 2 个免费 key

| Key | 用途 | 申请地址 | 注意 |
|---|---|---|---|
| 腾讯位置服务 Key | 后端抓 POI | https://lbs.qq.com/dev/console/key/manage | 建 key 时勾选 **WebServiceAPI**，域名白名单留空 |
| 天地图 Key | 前端地图底图 | https://console.tianditu.gov.cn/api/key | 类型选 **浏览器端** |

> 嫌麻烦不想申请天地图？把 `.env` 里 `MAP_PROVIDER` 改成 `amap` 就免 key 了，用高德的公开瓦片。
> 但那是非官方公开的瓦片接口，个人自用没问题，**不要用于对外服务**。

### 2. 配置环境变量

```bash
cp .env.example .env       # Windows: copy .env.example .env
```
编辑 `.env`，把两个 key 填进 `TENCENT_KEY` 和 `TIANDITU_KEY`。其他项保持默认即可。

> 一个 key 都没填也能启动，网页左上角会直接告诉你还差什么、去哪申请。

### 3. 安装 Python 依赖（建议 Python 3.10+）

```bash
python3 -m venv .venv
source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## 四、使用流程

1. 打开网页 → 左侧填**城市**（默认长沙）+ 可选**区域**（如"雨花区"）
2. 选**抓取深度** → 点「开始分析」
3. 等待十几秒到 2 分钟（取决于深度），过程中在跑：
   - 按 12 个菜系关键词分片抓 POI（绕开单次查询的结果条数上限），去重
   - 规则层用连锁词库快速筛掉奶茶/卤味/连锁
   - 给剩下的独立餐饮打用工需求分
   - 按商圈聚合（没有商圈标注的按 ~800m 空间聚类，命名成"XX路一带"）
4. 完成后地图上出现彩色圆圈：
   - 🔴 红色 = 高匹配商圈（独立餐饮里 ≥50% 有用工需求）
   - 🟠 橙色 = 中等（25–50%）
   - ⚪ 灰色 = 低（<25%）
5. 点击圆圈或左侧商圈列表 → 弹出该商圈的 Top 候选商户 + 直接跳转到 58/美团/高德验证招聘信息和销量
   （鼠标悬停在「用工分」上能看到这个分是怎么算出来的）

## 五、三种打分引擎怎么选

在 `.env` 里改 `LLM_PROVIDER` 一行即可切换，**不用改代码**。

| 选项 | 说明 | 成本 | 什么时候用 |
|---|---|---|---|
| `none`（默认） | 纯规则打分，词库在 `data/labor_keywords.txt` | 免费，零延迟 | **绝大多数情况**。开箱即用，几百家店毫秒出结果 |
| `zhipu` | 智谱 `glm-4.7-flash` | 永久免费 | 想要更细的语义判断时。注册拿 key: https://open.bigmodel.cn/usercenter/apikeys |
| `ollama` | 本地跑 `qwen3:8b` | 免费、离线 | 数据完全不出门。先 `ollama pull qwen3:8b`，INT4 量化约需 5–6GB 显存/内存 |
| `siliconflow` | 硅基流动免费模型 | 免费额度 | 智谱额度不够时的备选 |
| `deepseek` | DeepSeek | **按量付费** | 你已经充过值、且确实需要它的效果 |
| `custom` | 任意 OpenAI 兼容端点 | 看你接谁 | 需同时填 `LLM_BASE_URL` 和 `LLM_MODEL` |

> **AI 挂了不会把数据搞砸**：任何一批 AI 调用失败（超时、欠费、key 错），那一批会自动回落到规则打分，
> 而不是把这些店判成 0 分废掉。分析结果里会标注"AI不可用，规则估分"。

## 六、自定义规则

### 1. 扩充连锁品牌词库

编辑 `data/chain_brands.txt`，按文件顶部说明分组添加品牌名。**保存后下次「开始分析」立即生效，不用重启服务。**

### 2. 调整用工需求打分

编辑 `data/labor_keywords.txt`，里面是 `关键词=分值` 的形式，分四组：

- `#B` 基础分：按菜系/业态定基准（火锅 78、面馆 45、早餐 28……）
- `#P` 加分项：规模信号（酒楼 +15、旗舰店 +10……）
- `#M` 减分项：小微/外卖信号（外卖 -12、档口 -10……）
- `#N` 夜间项：24小时 +12、夜市 +10……

命中规则：**店名比数据源给的粗类目优先**（腾讯给所有餐馆都打"美食:中餐厅"，不这样处理的话面馆会被抬到跟正餐一个档）。同样保存后立即生效。

### 3. 调整"有用工需求"阈值

`.env` 里的 `LABOR_THRESHOLD=60`，调高=更严格（更少店被算作高需求），调低=更宽松。

### 4. 调整商圈聚类粒度

`.env` 里的 `GRID_SIZE_M=800`，调小=商圈切得更细，调大=更粗。

### 5. 修改默认城市

`.env` 中 `DEFAULT_CITY=` 改为你的城市。

## 七、从 v0.1 升级

在项目目录双击 **`update.bat`**，然后：

```bash
pip install -r requirements.txt     # 依赖有升级，这步不能省
python -m backend.main
```

`update.bat` 会自动：
- 保留你的 `.env`（并备份成 `.env.bak`）
- **保留你改过的词库**——如果 `chain_brands.txt` / `labor_keywords.txt` 和官方版本不一样，会保留你的，官方新版另存为 `.new` 供你参考（旧版的 update.bat 会直接覆盖掉你的修改）
- 清理已废弃的旧模块（`backend/amap.py`、`backend/deepseek.py`）

升级后 `.env` 里这几项已经**不再需要**，可以删掉：
`AMAP_FRONTEND_KEY`、`AMAP_FRONTEND_SECRET`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`

需要新增的是 `TENCENT_KEY` 和 `TIANDITU_KEY`（见[第二节](#二准备工作10-分钟)）。

## 八、合规与边界

- 仅抓取腾讯/高德开放平台的**公开 POI 数据**，请求频率受官方接口限速保护，代码里也做了礼貌间隔
- **不抓**美团/大众点评/58/BOSS 等需登录或反爬严格的平台；这些平台的验证靠地图上的「58/美团/高德」按钮**手动点击**到对应搜索页人工核实
- `MAP_PROVIDER=amap` 用的是高德公开瓦片接口，非官方文档承诺的用法，**仅限个人自用**；对外提供服务请用 `tianditu`
- 抓取到的商户联系方式仅供个人地推拜访使用，**严禁批量电销/短信骚扰**，否则违反《反电信网络诈骗法》
- 工具纯个人自用，不对外提供服务、不转售数据

## 十、常见问题

**Q: 启动后网页左上角提示"未配置 POI 数据源"**
A: `.env` 里没填 `TENCENT_KEY`。点提示里的链接去申请，免费的。（v0.1 遇到这种情况是直接启动失败报 `RuntimeError`，v0.2 改成了照常启动 + 页面提示。）

**Q: 提示"腾讯位置服务配额已用完"**
A: 个人开发者 10,000 次/日、每秒 5 次。到日限就等明天，或临时改 `POI_PROVIDER=amap` 用高德的月度额度顶一下。

**Q: 地图上店铺位置整体偏了几百米**
A: 说明坐标系没对上。POI 是 GCJ-02，天地图/OSM 底图是 WGS-84，程序会自动纠偏（`backend/geo.py`）。如果你手动改过 `MAP_PROVIDER`，确认改的是 `.env` 而不是代码里的默认值，然后**重启服务**。

**Q: 地图一片空白，只有彩色圈没有底图**
A: 天地图 key 没填或填错。检查 `TIANDITU_KEY`，或先改成 `MAP_PROVIDER=amap` 验证其他部分是否正常。

**Q: 页面提示"地图库 Leaflet 没加载成功"**
A: `frontend/vendor/leaflet/` 目录不完整，多半是更新时没拷全。重新跑一次 `update.bat`。

**Q: 抓回来的店太少**
A: 把"抓取深度"调大。程序按 12 个菜系关键词分片查询再去重，深度越大每个分片翻的页数越多。想扩大覆盖面还可以在 `backend/poi.py` 的 `CUISINE_SHARDS` 里加菜系词。

**Q: 用了 Ollama，很慢 / 报连接失败**
A: 先确认 `ollama serve` 在跑、`ollama pull qwen3:8b` 已完成，端口是默认的 11434。8B 模型跑几百家店本来就慢，建议先用默认的 `LLM_PROVIDER=none`。

**Q: 想跑其他城市怎么办？**
A: 直接前端"城市"框输入城市名（如"成都"、"杭州"）即可，不需要改代码。连锁词库的覆盖度对所有一二线城市基本通用。
